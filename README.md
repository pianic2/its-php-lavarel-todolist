## About

Laravel Todo List is a server-rendered task management application built with Laravel. It allows authenticated users to create task lists, manage tasks inside each list, filter work by status, and share lists with other registered users.

The project is aimed at small personal or collaborative workflows and uses a conventional Laravel MVC approach with Blade views, Eloquent models, Fortify-based authentication, database persistence, and mail notifications for shared lists.

## Installation

### Local setup

```bash
git clone <repository-url>
cd its-php-lavarel-todolist/todo-app
cp .env.example .env
touch database/database.sqlite
composer setup
php artisan db:seed
php artisan serve
```

The application is then available at `http://127.0.0.1:8000`.

### Frontend development server

If you want Vite running in watch mode instead of using the production build generated by `composer setup`:

```bash
cd /path/to/its-php-lavarel-todolist/todo-app
npm run dev
```

## Usage

### Start the development environment

```bash
cd /path/to/its-php-lavarel-todolist/todo-app
composer dev
```

This starts Laravel, the queue listener, log tailing, and the Vite development server in parallel.

### Local URLs

- Application: `http://127.0.0.1:8000`
- Docker app service: `http://127.0.0.1:8000`
- phpMyAdmin: `http://127.0.0.1:8080`

### Minimal usage flow

1. Open the application in the browser.
2. Login with the demo account or register a new user.
3. Create a list.
4. Open the list and add tasks.
5. Mark tasks as completed or filter them by status.
6. Share a list with another registered user by email.

## Automatic Bootstrap

Two automated bootstrap paths are present in the repository:

- `composer setup` installs PHP dependencies, creates `.env` if missing, generates the application key, runs migrations, installs frontend dependencies, and builds assets.
- `deploy/start-render.sh` prepares production startup by generating a valid `APP_KEY` if needed, creating the SQLite file when missing, running migrations and seeders, caching Laravel configuration/routes/views, and starting the application.

## Authentication

The application uses Laravel Fortify with session-based web authentication.

- Public routes: authentication views and flows for login, registration, password reset, and email verification.
- Protected routes: the home page, list CRUD, task CRUD, task toggle, list sharing, and access revocation.
- Login field: email.
- Rate limit: login attempts are throttled to five requests per minute per email and IP combination.

No bearer token flow is documented or required by the current application. After login, access is handled through the web session.

## Data Validation

The project validates incoming data at controller/Form Request level.

- Lists: `name` is required, must be a string, and has a maximum length of 255 characters; `description` is optional and must be a string when provided.
- Tasks: `title` is required, must be a string, and has a maximum length of 255 characters; `description` is optional and must be a string; `is_completed` is optional and must be boolean.
- Sharing: `email` is required, must be a valid email address, and must already exist in the users table.
- Task filters: only `all`, `open`, and `done` are accepted.

## Data Model

```text
users
	id, name, email, password, email_verified_at, timestamps

lists
	id, name, description, timestamps

tasks
	id, list_id, title, description, is_completed, timestamps

list_user
	id, user_id, list_id, timestamps
```

Main relationships:

- One list has many tasks.
- One task belongs to one list.
- Users and lists are linked through a many-to-many pivot table.
- The `list_user` pair is unique, so the same user cannot be attached to the same list twice.

## Architecture

```text
Browser
	|
	v
Laravel Routes
	|
	v
Controllers + Fortify
	|
	+--> Blade Views
	+--> Notifications (Mail)
	|
	v
Eloquent Models
	|
	v
SQLite / MySQL
```

The application follows a standard Laravel MVC structure. Routes delegate to controllers, controllers coordinate validation and business rules, Eloquent manages persistence, Blade renders the HTML interface, and Fortify handles the authentication flow.


## Storage

- The default Laravel database configuration uses SQLite.
- The Render deployment is configured to use `database/database.sqlite` inside the application directory.
- The Docker Compose environment defines a persistent MySQL volume named `db_data`.

## Features

- Create and organize multiple task lists.
- Add, edit, delete, and toggle task completion.
- Filter tasks by status.
- Share lists with other registered users.
- Send email notifications when a list is shared.
- Use a server-rendered Laravel Blade interface.
